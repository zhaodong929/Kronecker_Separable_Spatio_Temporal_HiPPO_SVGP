# KronHiPPO-SVGP implementation and theorem audit

Reviewed implementation commit `4f881c7ee9de5ec203b1bd79589627c1f1f3417b`, manuscript `f0e7e46`, and read-only current remote proposal artifacts on 2026-09-30. No source, jobs, or commits changed. The conclusions below concern the proposed method; cross-method result admission still requires the other adapters' audits. Policy: `/data/nk523/ObsidianVault/03-projects/hipposvgp/2026-09-29-baseline-selection-policy.md`.

## Overall finding

The transported joint Gaussian update is mathematically coherent. I found no demonstrated current/future target leak in its assimilation order. The important distinction is that ERA5 uses the fixed-geometry Schur–Sylvester implementation, while COVID and PEMS use a sum-of-Kronecker, preconditioned-CG extension. The paper's conditional fixed-geometry theorem remains valid, but that theorem does not establish the COVID/PEMS extension's cubic solve complexity. Current completed COVID/PEMS predictions can remain candidate results after the common protocol checks; rejecting them merely because they use CG, frozen kernel parameters, an adaptive joint mean, or a nominal 250-iteration cap would be unsupported.

## Findings by severity

### High: the single-Sylvester complexity theorem does not cover the delayed-label experiments

**Known.** The manuscript explicitly assumes unchanged spatial observation/inducing functionals, Cartesian blocks, homoscedastic Gaussian noise, and fixed hyperparameters: `/data/nk523/projects/hipposvgp-overleaf-6aba8fcfb715ddc40d02c0d2/main.tex:354`, `:360`, `:429`. Under these assumptions, transporting `B ⊗ G` by `L_t ⊗ I` and adding `TᵀT ⊗ G / σ²` preserves the invariant. The Schur/Sylvester dense-equivalence theorem is valid for that resulting finite Gaussian target, conditional on SPD and numerical regularization; it is not a full-GP exactness theorem.

Current implementation selects multi-geometry when delayed observations are enabled **or** Task-1 and stream observation sites differ: `/data/nk523/projects/hipposvgp-fair-comparison/scripts/run_iclr_era5_routeb_strict_online.py:505`. COVID starts from all 52 sites and subsequently has visible and delayed-hidden geometries; PEMS has visible and delayed-hidden geometries. Their workers explicitly request delays: `/data/nk523/projects/hipposvgp-fair-comparison/slurm/fair_three_domain/covid_tracked_worker.sh:21` and `/data/nk523/projects/hipposvgp-fair-comparison/slurm/fair_three_domain/pems_tracked_worker.sh:21`.

The extension correctly retains separate `(G_j,B_j)` terms, transports every `B_j`, and merges only exactly equal spatial Grams: `/data/nk523/projects/hipposvgp-fair-comparison/stvgp_kronecker/joint_ssgp_kron/multi_geometry.py:135`. It solves `K_t⁻¹ ⊗ K_s⁻¹ + Σ B_j ⊗ G_j` by CG (`:17`, `:33`, `:44`), not a single Sylvester inverse. Its docstring explicitly disclaims the fixed-geometry guarantee (`:1`). Memory remains independent of elapsed stream length **for a bounded set of spatial geometries**; arbitrary masks/new geometries could accumulate terms.

**Minimal remedy:** describe the extension and identify it in COVID/PEMS results, state CG tolerance/iteration failures, and restrict the cubic claim to the fixed-geometry core. For J terms and I CG iterations, one batched matvec scales with J times the usual matrix-product costs, and I is conditioning-dependent. Include mean dimension/right-hand-side counts and prediction costs. No extra baseline or ablation is needed. The abstract's broad cubic statement at manuscript `main.tex:69` needs this qualification if these experiments replace the old tables.

### High for efficiency claims: saved `update_seconds` excludes delayed assimilation

**Known.** The complete delayed posterior update is inside `factor_timer`, `/data/nk523/projects/hipposvgp-fair-comparison/scripts/run_iclr_era5_routeb_strict_online.py:757` through `:806`. The separately named `update_timer` covers only current-visible assimilation (`:867`). Reported `stream_update_seconds` and `mean_block_update_seconds` therefore omit a substantial update on COVID/PEMS (`:1055`). The work is counted in factor-preparation/process totals, so this is a reporting-scope issue, not missing computation.

**Minimal remedy:** use factor preparation + update + prediction (+ feature handling under a common definition) for online comparisons, and list Task-1 calibration/posterior initialization separately. Existing block logs can support this correction without rerunning prediction. Do not compare this field directly with a baseline's full delayed-plus-current update time.

### Medium: bounded inference state is distinct from the runner's memory use and temporal-factor overhead

**Known.** The paper's detailed cost explicitly excludes data loading, statistic formation, Task-1, and all-point prediction: `/data/nk523/projects/hipposvgp-overleaf-6aba8fcfb715ddc40d02c0d2/appendix.tex:157`. The runner loads the entire stream, retains prediction grids and lists, and checkpoints all prior predictions/metrics: `/data/nk523/projects/hipposvgp-fair-comparison/scripts/run_iclr_era5_routeb_strict_online.py:437`, `:626`, `:960`. Its `persistent_state_bytes` only counts selected model/state objects (`:918`), and `history_replay_buffer_bytes=0` (`:1074`) means no replay dataset in the inference state, not constant total process RAM.

There is also horizon-dependent factor work outside the core solve: `/data/nk523/projects/hipposvgp-fair-comparison/stvgp_kronecker/joint_ssgp_kron/synthetic.py:353` sorts/differences the complete supplied time array for a grid step, while `/data/nk523/projects/hipposvgp-fair-comparison/stvgp_kronecker/temporal_analytic.py:352` constructs a timestamp vector (`:298`) even when the caller discards it. On cumulative horizons its length grows. The Torch Bessel recurrence depth additionally depends on maximum argument (`:75`); current frozen inference workers choose SciPy instead. These facts do not disprove the posterior-solve theorem.

**Minimal remedy:** retain the core-state claim, separately report peak RSS/device memory and full update totals, and avoid asserting constant full-run memory or horizon-independent complete update cost. Any later implementation cleanup can cache grid metadata/remove unused timestamp construction; it is not required to discard existing accuracy results.

## Mathematical exactness and initialization

The method transfers an expected **log** historical likelihood: `R ← MᵀRM`, `h ← Mᵀh`. Conditional covariance contributes a state-independent trace term for fixed hyperparameters. This matches manuscript `main.tex:308` and appendix `appendix.tex:23`, and the implementation `multi_geometry.py:144`. It is not marginalization of the old likelihood and not general equality to a batch posterior rebuilt from raw history. The manuscript already limits the one-step L2 projection/variance identity and explicitly disclaims globally lossless repeated transfer (`main.tex:330`, `:350`). The Gaussian quadratic variance derivation in `appendix.tex:34` is correct under the stated prior conditional law; “optimal” should retain that local L2 meaning, not posterior-KL or forecasting optimality.

Analytic HiPPO means analytic Legendre/Fourier projection using spherical Bessel functions, avoiding a numerical HiPPO ODE integration. It does not remove RFF approximation: `/data/nk523/projects/hipposvgp-fair-comparison/stvgp_kronecker/temporal_analytic.py:319` constructs the finite basis, `:360` uses `variance * ZᵀZ`, and `:384` uses finite query features. Cross-covariance uses the **same** feature expansion (`:365`, `:434`). Spatial inducing projection and temporal finite representation remain approximation layers. “Exact finite target” and “analytic basis” can be retained; “exact original kernel/GP posterior” cannot.

The proposal freezes selected kernel/noise parameters, initializes a new joint posterior from legal Task-1 rows, and then carries likelihood sufficient statistics. It does not simply reuse a validation posterior containing the held-out inner sites. See `/data/nk523/projects/hipposvgp-fair-comparison/scripts/run_iclr_era5_routeb_strict_online.py:398`, `:644`, `:674`. Refitting on all *legally available* Task-1 sites after selection is legitimate. Cached ERA5 calibration results require matching numerical-source/input/result hashes and a completed tracked validation lineage: `/data/nk523/projects/hipposvgp-fair-comparison/benchmarks/three_domain/reuse_validation.py:43`, `:52`. Reuse itself is not information leakage.

## Horizontal comparison and information boundary

The proposal's Bayesian beta and beta–GP cross block evolve online (`torch_backend.py:454`, `:479`; full absolute path `/data/nk523/projects/hipposvgp-fair-comparison/stvgp_kronecker/joint_ssgp_kron/torch_backend.py`). This is a substantive model difference from the Task-1 ridge offsets in baselines. Shared covariate **availability** does not imply the same fitted mean/predictive uncertainty. For example, ST-SVGP subtracts/adds a fixed causal mean (`/data/nk523/projects/hipposvgp-fair-comparison/baselines/covid_long_setting_b/adapters/run_st_svgp.py:428`); OHSVGP keeps the fit-site ridge coefficients but refits residual state on legal initial sites (`/data/nk523/projects/hipposvgp-fair-comparison/scripts/run_covid_ohsvgp_own_theta.py:458`), freezes kernel/likelihood (`:472`), then updates variational state. The OHSVGP campaign independently validates capacity, initial budget, online rate and update count (`/data/nk523/projects/hipposvgp-fair-comparison/scripts/run_ohsvgp_final_campaign.py:73`). OSGPR has adaptive kernel/inducing optimization (`/data/nk523/projects/hipposvgp-fair-comparison/scripts/run_official_bui_osgpr_era5.py:370`); MGPVAE's campaign declares frozen online parameters (`/data/nk523/projects/hipposvgp-fair-comparison/scripts/run_mgpvae_final_campaign.py:102`). These are legitimate system choices to state in the table, not proof of unequal label access. They limit causal attribution of a score difference to the solver or HiPPO alone. MGPVAE with a shared offset also does not isolate “mean+GP” versus an entirely independent end-to-end modeling choice.

For COVID/PEMS, pending hidden observations are popped once, evaluated at the original temporal slice with the current old basis, then assimilated with hidden geometry before the current visible block and prediction (`/data/nk523/projects/hipposvgp-fair-comparison/scripts/run_iclr_era5_routeb_strict_online.py:764`, `:772`, `:798`, `:868`, `:879`). Hidden labels for scoring are materialized in a test factor, but only its T/Phi/C enter `predict_with_C`; y is not passed (`:856`, `:879`). Pending labels are queued after prediction (`:952`). Current visible labels condition the same-time hidden prediction: this is partial-observation online reconstruction, not unconditional future forecasting. ERA5 has no hidden-label releases.

The current prediction defaults include conditional GP residual variance, noise, posterior inducing uncertainty and the Schur-adjusted mean uncertainty (`/data/nk523/projects/hipposvgp-fair-comparison/scripts/run_iclr_era5_routeb_strict_online.py:232`; `/data/nk523/projects/hipposvgp-fair-comparison/stvgp_kronecker/joint_ssgp_kron/multi_geometry.py:187`). Old finite-DTC scores should not be silently merged with this setting.

## Numerical verification and usable current results

CG refuses nonpositive search curvature, recomputes the true residual before acceptance, and raises after 512 iterations; tolerance is 1e-9 with explicit residual acceptance at 1e-8 (`/data/nk523/projects/hipposvgp-fair-comparison/stvgp_kronecker/joint_ssgp_kron/multi_geometry.py:18`, `:60`, `:67`, `:86`). It also checks finite/positive predictive variances and materially negative conditional residuals (`:193`). Cholesky uses scaled jitter and retries up to 10,000 times its base (`/data/nk523/projects/hipposvgp-fair-comparison/stvgp_kronecker/joint_ssgp_kron/torch_backend.py:40`). Successful jitter is not logged there, so exactness claims must remain “up to declared regularization”; a residual bound alone is not a conditioning-independent posterior-error bound.

Ran a bounded remote CPU-only suite with OMP/BLAS/MKL threads set to two: 12 passed, 4 CUDA tests skipped, 23.15 seconds. Tests were multi-geometry dense joint mean/covariance/prediction parity, Torch backend, analytic gradients, and true-label boundary/resume. **Scope caveat:** `/vol/bitbucket/nk523/hipposvgp-fair-20260929/source` has older temporal/runner and two test files than review HEAD. SHA256 matched both solver implementations and their two corresponding tests exactly; therefore those solver checks directly support current reviewed code. The older end-to-end/gradient successes are supplementary, not an assertion that current HEAD's full suite ran. Current boundary test source independently checks perturbing unreleased targets, effect after release, future-target invariance, and resume equality: `/data/nk523/projects/hipposvgp-fair-comparison/tests/test_strict_online_release_boundary.py:39`.
