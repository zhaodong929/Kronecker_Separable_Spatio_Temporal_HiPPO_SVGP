## Conclusion

The reports' corrected ST timing interpretation, Gaussian/mixture arithmetic, and distinction between completion and scientific admission are supported. Two additional measurement boundaries need explicit treatment: proposal feature work must join its other online timers, and OSGPR/OHSVGP omit query/offset preparation between their recorded timers. Consequently the currently available sums are not exactly the same end-to-end latency estimand. This is not evidence of incorrect predictions and does not itself require retraining. Frozen versus adaptive parameters and different capacity grids are legitimate stated method configurations; neither demands identical iteration counts or unrestricted tuning.

## Concrete timing crosschecks and omissions

Paths below are relative to `/data/nk523/projects/hipposvgp-fair-comparison`.

1. **Proposal feature time is another measured component.** `scripts/run_iclr_era5_routeb_strict_online.py:739` starts `feature_started`, calls `phi_cache.block` and optional projection, and records `feature_seconds` before `factor_timer` starts at line 757. The cumulative field is separately updated at line 917. Therefore factor preparation + current update + prediction is a useful subtotal, but a decision-to-prediction comparison should also include this required feature retrieval/projection time. The reported PEMS 4351.048 seconds must be described as that subtotal unless its feature contribution is added. Delayed-label assimilation really is inside factor preparation, as both earlier reports state. Test scoring and archive writes can remain separately accounted evaluation overhead.

2. **OSGPR/OHSVGP sums omit required query preparation.** In `scripts/run_official_bui_osgpr_era5.py:511`, update timing stops before `x_test`, `y_test` and `offset_test` construction; prediction starts afterward at line 516. In `scripts/run_covid_ohsvgp_own_theta.py:555`, the analogous `x_test` and `test_offset` preparation is also outside both timers; adding the offset at line 562 is outside prediction timing. Target extraction for scoring can be excluded, but constructing inputs/offsets is inference work. ST's event interval at `baselines/covid_long_setting_b/adapters/run_st_svgp.py:435`–448 includes protocol access, residual means and prediction mean offset; MGP's event interval at `scripts/run_mgpvae_causal.py:218`–238 similarly includes these. The omitted time is not separately measured in the OSGPR/OHSVGP rows. Do not silently advertise identical timing boundaries merely by summing fields with similar names. Existing totals may be labelled with their scopes; a narrowly scoped latency measurement from saved fitted states can resolve publication comparisons without rerunning model selection solely for this reason.

3. **GPU phase subdivision is weaker than synchronized total latency.** OHSVGP's `export_state` at line 197 returns GPU tensors, without explicit device synchronization. Its prediction returns CPU NumPy arrays at line 220. Some outstanding update work can therefore be charged to the next prediction interval; the combined interval reaches a synchronization boundary. This does not establish that the combined time loses GPU computation, but its update-only versus prediction-only breakdown is not a clean device-phase attribution. Proposal explicitly uses synchronized timers. Compare combined latency with consistent boundaries before interpreting phase-specific speedups.

4. **There is real implementation overhead in OH beyond its mathematical update.** At `scripts/run_covid_ohsvgp_own_theta.py:522`, `stream_y - stream_mean` forms a full-stream residual array within each observation update before `flatten_values` selects the current rows. This is included in measured update time, and at long horizons is avoidable repeated data preparation. It does not read future labels into model fitting—the selected slice is still the authorized observation block—but it means measured runtime cannot be attributed entirely to the official inference algebra or used as a pure asymptotic-method comparison. This is a code-level cleanup candidate, not grounds to change the model or declare existing accuracy invalid.

5. **ST interpretation in the final reports is correct.** Its `task1_seconds` is final refit cost; the continuation-minus-event-timer residual includes initial filtering plus all untimed continuation logging/checkpoint work, not just filtering. Current PEMS numbers therefore mean approximately 1326.92 seconds final refit, 242.57 seconds timed online event work, and 352.39 seconds whole continuation. Calibration exploration is additional. The old COVID full-prefix replay runtime cannot represent current qualified continuation. First-use compilation included in an online timer should be labelled; compare full online phase including that cost, or separately measured warm-event latency, consistently.

The policy also explicitly requires comparable uncontended hardware for publication speed/memory measurements. A matching GPU model alone does not establish matching GPU/CPU contention, thread counts, precision or compilation state. This crosscheck did not establish whether every current run is uncontended, so that remains a provenance check rather than an accusation. Report actual campaign elapsed/GPU expenditure separately from clean inference latency. Across COVID/ERA/PEMS, an event has different site counts, delay updates and physical cadence; total hours or average milliseconds across the three datasets is not a meaningful pooled speed ranking.

## Predictive scores and their statistical meaning

- Direct inspection supports the Gaussian observation-density NLPD and analytic CRPS in `benchmarks/three_domain/evaluation.py:8`, including the positive-variance guard. The scale transform at line 21 correctly multiplies RMSE/CRPS and adds log scale to NLPD. This only undoes affine standardization; COVID remains on the log1p-admissions-per-100000 target, not raw counts.
- `benchmarks/three_domain/metrics.py:6` correctly implements equal-weight Gaussian mixture log density and CRPS, including diagonal component pairs. Its calibration function uses the finite-mixture CDF to test central interval coverage; this avoids an inappropriate moment-Gaussian approximation. `baselines/mgpvae/gpu_metrics.py` uses the same formula and requires float64. No scoring formula defect was found here.
- These are exact scores of the **finite sampled mixture**, not exact integration of the decoder's latent predictive law. The final campaign uses 512 components (`scripts/run_mgpvae_final_campaign.py:25`). The existing 128/256 subsample diagnostics at `scripts/run_mgpvae_causal.py:129` support sensitivity assessment but are not an automatic bound on all stream MC errors. The MGP specialist already found small COVID sensitivity without an ordering reversal; this review does not contradict that or require new training. If two results are close on the scale of this approximation, use saved latent/model artifacts for targeted density reevaluation before declaring a ranking.
- Gaussian and mixture scores concern scalar site-time marginals. They do not evaluate joint spatial/temporal predictive dependence. The paper can claim marginal probabilistic accuracy/calibration, not superior joint field uncertainty from these metrics alone. No extra metric suite is required if wording remains scoped.
- ECE here is average absolute deviation of pooled central-interval coverage over ten levels `.05,.15,...,.95`; coverage90 is separately computed. It is not classification confidence ECE or a proper scoring rule. NLPD/CRPS provide proper distribution scores; a model with good pooled ECE can still miscalibrate particular sites or seasons. A limited pooled-calibration claim is valid without adding an ablation.
- Equal per-event pooling in the current mixture evaluator is appropriate because each run has a fixed query-site count. Query counts vary across datasets, so do not aggregate all raw rows into one headline score. Each method should first be compared on paired masks within each dataset and target scale.

## Selection, capacity and replication

The initial gate `benchmarks/three_domain/convergence.py:4` accepts an interior validation optimum or an explicitly declared objective/ELBO plateau at the endpoint. This is a selection-budget criterion, not proof of global optimization convergence. The method campaigns have different grids and stopping implementations; write their actual selected values and stopping reasons. A finite declared capacity grid is a legitimate resource-bounded comparison. Selecting its largest capacity is not mathematically equivalent to an unresolved training-iteration endpoint and does not automatically require endless capacity expansion. Conversely, an interior checkpoint does not prove every untried capacity would be inferior.

The OH and OS online-budget campaigns compare extra updates by validation NLPD and use a 0.01 improvement threshold (`scripts/run_ohsvgp_final_campaign.py:99`, `scripts/run_osgpr_final_campaign.py:103`). This is a declared materiality threshold, not a statistical significance test. Frozen ST/MGP parameters do not need a synthetic online optimizer search; they do need valid own initial selection and an honestly stated frozen policy. Proposal's jointly evolving Bayesian mean versus baselines' fixed ridge offset limits solver-only causal attribution but is not, by itself, unequal label access. Do not require equal parameter counts or remove an actual contribution to force superficial symmetry.

`scripts/summarize_verified_campaign.py:38` aggregates only complete paired datasets and uses sample SD. Five masks on the same period (three for PEMS), with overlapping sites, are not five independent datasets or a pure optimizer-seed study. Descriptive mean/SD and paired differences are appropriate. Temporal error summaries can be derived from saved predictions, but neither individual site-time counts nor a collection of daily means automatically supplies independent replication. Current evidence supports performance on these three tasks and masks; it does not establish universal superiority over unseen domains.

## Minimal effect on result admission

Timing-label changes, inclusion of already saved feature timers, score-scale presentation and narrower uncertainty/statistical claims do not require accuracy retraining. Missing clean latency scope can be addressed by bounded measurement with saved states. A method's verified parameter-state bug or a change in the model's actual input clock is different and can require its own affected selection/inference rerun; those decisions belong to the implementation and protocol reports. Keep implementation correctness, common information/clock contract, validation adequacy, metric validity and timing comparability as separate admission checks. This review identifies no additional numerical prediction bug beyond the other specialists' findings and proposes no extra baseline or ablation.
